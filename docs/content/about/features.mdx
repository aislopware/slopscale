title: "Features"
---

Slopscale is a self-hosted, open source implementation of the Tailscale control server, run as a single binary with
its CLI and an [admin console](/ref/console). This page lists what it supports of Tailscale's feature set, what it adds
of its own, and what it does not do. Each item links to the page that explains it.

## Tailscale features

- [x] [Node registration](/ref/registration): [web authentication](/ref/registration#web-authentication),
      [pre-authenticated keys](/ref/registration#pre-authenticated-key) and
      [OpenID Connect](/ref/oidc), with [device and user approval](/ref/approval)
- [x] [OpenID Connect](/ref/oidc): profile sync, allowed domains, emails and groups, group sync into
      [slopscale groups](/ref/access-control#groups), and [switching providers](/ref/oidc#switching-oidc-providers) by
      matching on email
- [x] [User roles](/ref/roles): owner, admin, network admin, IT admin, auditor and member, bounding the admin API and
      the console
- [x] [DNS](/ref/dns): MagicDNS, global and split nameservers, search domains,
      [extra records](/ref/dns#setting-extra-dns-records), [split DNS per group](/ref/dns#split-dns-per-group),
      nameservers kept while an exit node is in use, all changeable at runtime
- [x] File sharing: [Taildrive](https://tailscale.com/docs/features/taildrive) and
      [Taildrop](https://tailscale.com/docs/features/taildrop)
- [x] [Tags](/ref/tags)
- [x] [Routes](/ref/routes): [subnet routers](/ref/routes#subnet-router), [exit nodes](/ref/routes#exit-node),
      [suggested](/ref/routes#suggested-exit-nodes) and [global](/ref/routes#global-exit-node) exit nodes,
      [high availability](/ref/routes#high-availability) with [regional routing](/ref/routes#regional-routing), and
      route filtering with [via](https://tailscale.com/docs/features/access-control/grants/grants-via)
- [x] [Apps and app connectors](/ref/apps)
- [x] [Tailscale Services](/ref/services)
- [x] Dual stack (IPv4 and IPv6) and [IP pools](/ref/policy#ip-pools)
- [x] [Ephemeral nodes](/ref/registration#ephemeral-nodes), by key or by the client's own request
- [x] Embedded [DERP relay](/ref/derp), on by default, and relays managed at runtime
- [x] [Peer relays](/ref/networks#peer-relays)
- [x] [Policy](/ref/policy): ACLs, grants, [autogroups](/ref/policy#autogroups) including the role autogroups,
      `autogroup:shared` and `autogroup:self`, [auto approvers](/ref/routes#automatically-approve-routes-of-a-subnet-router),
      [node attributes](/ref/policy#node-attributes) including `app` and `ipPool`, Tailscale SSH, `tests` and `sshTests`
- [x] [Device trust](/ref/device-trust): [device posture](/ref/device-trust#device-posture) and postures in the policy
      and in access rules, [hardware attestation](/ref/device-trust#hardware-attestation),
      [posture integrations](/ref/device-trust#posture-integrations) with CrowdStrike Falcon, SentinelOne, Intune,
      Jamf Pro, Kandji and Kolide, and [suspending a machine](/ref/device-trust#suspending-a-machine)
- [x] [Node sharing](/ref/sharing)
- [x] [Tailnet lock](/ref/tailnet-lock)
- [x] [Identity tokens](/ref/identity-tokens) (`tailscale id-token`)
- [x] [Serve](https://tailscale.com/docs/features/tailscale-serve) with [HTTPS certificates](/ref/https-certificates)
      from Let's Encrypt
- [x] [Funnel](/ref/funnel), through an ingress node you run
- [x] [SSH session recording](/ref/ssh-recording), with an embedded recorder
- [x] [Key expiry](/ref/approval#key-expiry) as a tailnet setting
- [x] [Webhooks](/ref/webhooks) in Tailscale's delivery format, and [log streaming](/ref/log-streaming) to Splunk,
      Elastic, Datadog, Axiom, Loki or any HTTP sink
- [x] [Audit log](/ref/audit)
- [x] [Device management over the control connection](/ref/device-management): client updates, health, diagnostics
      and managed preferences
- [x] Client update notices, so an old client shows Tailscale's own update warning
- [x] [Tailscale-compatible API](/ref/api#tailscale-compatible-api) with OAuth clients and scopes, so the Terraform
      provider and the Kubernetes operator work unchanged, and workload identity federation for CI jobs

## Slopscale features

- [x] [Admin console](/ref/console) built into the binary, signing in through the identity provider
- [x] [Groups and access rules](/ref/access-control), for access without a policy file, with an
      [access graph](/ref/access-control#access-graph)
- [x] [Networks](/ref/networks): subnets and exit nodes handed to groups
- [x] [Temporary access](/ref/temporary-access): expiring rules and memberships, and access requests
- [x] [User invitations](/ref/console#inviting-users) by email and [console sessions](/ref/console#sessions) an
      administrator can end
- [x] [SSH from the console](/ref/console#ssh-from-the-console) with Tailscale's in-browser client
- [x] Notifications to Slack, Mattermost, Google Chat, Discord, Microsoft Teams, Telegram, ntfy and
      [email](/ref/webhooks#notifications)
- [x] [DNS](/ref/dns#changing-dns-settings-at-runtime) and [DERP](/ref/derp#configuration) settings stored in the
      database and changed without a restart
- [x] [Database backup and restore](/setup/backup) while the server runs
- [x] Relay [latency](/ref/derp#latency) reported by every client
- [x] A control dial plan, so clients keep the server's addresses through a DNS outage
- [x] A [REST API](/ref/api#rest-api) with an OpenAPI 3.1 document and interactive docs at `/api/v1/docs`

## Not available

- [ ] [Network flow logs](https://tailscale.com/docs/features/logging/network-flow-logs): the client sends them to a
      host it does not let a control server change
- [ ] Tailscale's hosted Funnel ingress: [Funnel](/ref/funnel) needs an ingress node of your own
- [ ] [IP sets](https://tailscale.com/docs/features/tailnet-policy-file/ip-sets) in the policy file
- [ ] Contacts and the AWS external ID of the Tailscale API: the Terraform resources for them are refused with an
      explanation
